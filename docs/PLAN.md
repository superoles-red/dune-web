# План: Dune (Sega) — BYOP-порт `dune-web`

Основание: [STRATEGY.md](../Порты%20игр/STRATEGY.md) §5.3, §9.1 (планы workspace).
Спайк пройден 2026-11-27 — отчёт: `Порты игр/spikes/dune-recompiler/REPORT.md`.

## Цель

Игрок приносит ROM (USA, 1 048 576 байт). Оболочка проверяет дамп, перекомпилирует программу
Sega **на устройстве** (без эмулятора), кэширует результат и запускает ту же игру с теми же
кампаниями, картами, экономикой и поведением. Фронтенд (тач, зум, меню, RU/EN) — наш; картинка
и правила — из ROM игрока.

## Критерии готовности (definition of done)

- старт до ~10 с после первой сборки (вторая — из кэша);
- импорт файла сохранения старой версии и продолжение миссии в новой;
- экспорт сохранения, переносимого между устройствами;
- офлайн после установки; обновление не ломает сохранения;
- честные требования на странице (iPhone Safari tab/Home Screen, Android Chrome);
- ни одного байта игровых данных в git и на Pages;
- известные дефекты перечислены.

## Ключевые технические решения

1. **Рантайм отдельно, игра из ROM.** Runtime-преамбула (`runtime/dune-runtime-v2.c`) — наш
   MIT-код адаптации + ReArrakis; она фиксирована и поставляется. Из ROM игрока генерируется
   только код игры. Это же сохраняет ABI сохранений `DSAV v2`.
2. **Сохранения.** Формат файла — как у старой версии (`dune-sega-web-save` v1, нативный payload
   `DSAV v2`, checksum sha256 по каноническому JSON). Новый порт обязан сохранять структуру
   `DuneSaveState` и смещения, иначе старые сейвы не перенесутся. Старые `engineSha256`
   принимаются; новый экспорт пишет идентичность нового порта.
3. **WASM на устройстве.** `runtime.wasm` (SDL2/VDP/звук/ввод) собирается заранее emcc 3.1.74;
   на телефоне Python-эмиттер из ROM генерирует `game.wasm` с обработчиками инструкций и
   связывает его с рантаймом через импорты/экспорты и общую линейную память. Дизайн и PoC —
   `docs/WASM-BACKEND.md`.
4. **Легальность.** В git/Pages только MIT-код и собственные скрипты. ROM, ядро, ассеты — только
   у игрока в браузере (память + OPFS) или на его диске.

## Проверено 2026-11-27

- `tools/verify.py` (26 проверок, 4,2 с): ROM → C побайтно равен подготовленному `dune-web.c`
  `d7c84066…` (20 417 216 байт); runtime `e47a4cae…`; преамбула `4d6181fd…`.
- `node --test tests/saves/*.test.mjs`: 29/29 — старый файл импортируется как есть.
- `node tests/browser/smoke.mjs`: сборка ядра в Chrome 8,36 с (discovery 5,16 + трансляция 3,02),
  SHA `d7c84066…`, второй прогон — из OPFS-кэша (`cached: true`).
- ABI сейвов: `sizeof(DuneSaveState)=140056` подтверждён компиляцией точной структуры из pinned
  baseline (natural alignment); структуру НЕЛЬЗЯ пересобирать из `vendor/.../dune_savestate.h`
  (там `#pragma pack(1)` → 140027 и поломка старых сейвов).
