# Точный runtime v2

Рантайм — это **кодовая часть** сгенерированного ядра: планировщик MC68000/Z80,
VDP, звук, SDL-хост, браузерные адаптеры ввода/презентации и сохранения `DSAV v2`.
Он не содержит ни байта ROM и ни одной транслированной игровой инструкции, поэтому
поставляется в репозитории как MIT-код. Из ROM игрока генерируется только игровая
часть; рантайм фиксирован и проверяется по SHA-256.

`runtime/dune-runtime-v2.c` — ровно то, что перекомпилятор получает через
`--pinned-runtime`. Полная преамбула сгенерированного C добавляет перед ним три
строки, которые эмиттер пишет сам:

```c
/* Generated by genesis-recompiler. Original ROM required at translation time. */
#define GENESIS_DUNE_MOUSE
#define GENESIS_WINDOW_TITLE "ReArrakis  Dune: The Battle for Arrakis"   // --window-title
<runtime/dune-runtime-v2.c>
static const uint8_t rom_data[] = { ... };   // игровые данные, внешние
<транслированный код 68000/Z80>              // из ROM игрока
```

`tools/bundle_web.py` копирует `runtime/<runtime_file>` в `web/py-src/dune-runtime.c`
и передаёт файл в `--pinned-runtime`; `--window-title` берётся из
`runtime/manifest.json` → `window_title`. Поэтому артефакт намеренно не содержит
трёх строк эмиттера: иначе они задвоились бы и SHA сверки не совпал.
`tools/verify.py` проверяет это тождество: `prefix + runtime + "\n" == preamble
подготовленного dune-web.c`.

## 1. Что такое преамбула и почему она безопасна

Преамбула — всё до маркера `static const uint8_t rom_data[] = {`. Это чистый C-код:

- ядро ReArrakis: шина/тайминги Genesis, VDP (рендер, DMA, CRAM/VRAM), PSG, YM2612
  через ymfm, Z80 bus/CPU/runtime, планировщик, контроллер, `DuneMouse`, `DuneView`,
  SDL2-фронтенд, `dune_savestate.h`;
- наши адаптеры (`#include "em_web_*.h"` + вставленный код);
- точки входа `run_main`, `sdl_host_service`, `em_main_loop_iter` (из `em_web_host.h`)
  и экспорты `EMSCRIPTEN_KEEPALIVE`.

Представление эмиттера о рантайме — `vendor/rearrakis/genesis_recompiler/runtime.h`
плюс заголовки; `--pinned-runtime` заменяет эту композицию целиком, поэтому она
может включать дополнительные `#include` адаптеров, которых у upstream нет.

Проверки «в преамбуле нет игровых данных» (в `tools/build_runtime.py`, повторяются в
`tools/verify.py`):

1. маркер `rom_data[]` отсутствует, `static const uint8_t rom_data[]` отсутствует;
2. артефакт — точный префикс подготовленного `dune-web.c` до маркера;
3. нет «байтовых рядов»: регулярное выражение `(0xNN,){16,}` не находит совпадений;
4. размер < 900 КБ (в 70 раз меньше ROM+кода) и > 50 КБ;
5. `#define DUNE_SAVESTATE_VERSION 2` присутствует, версии 1 нет;
6. все `#include "em_web_*.h"` принадлежат ровно 20 пиновым адаптерам.

`tools/check_no_game_data.py` дополнительно запрещает в git крупные тексты и
сниппеты `rom_data[]`/`rom_code[]`.

## 2. Чем v2 отличается от базовой генерации

Базовая версия (`dune-base.c`, она же v1) — результат ReArrakis-перекомпилятора без
браузерных патчей: преамбула 124 896 байт. v2 — та же базовая генерация после
`tools/prepare_source.py`: преамбула 130 103 байт (+5 207), 41 изменённый участок,
+137/−67 строк относительно эталонного runtime v1. Игровая часть (всё от маркера,
20 287 113 байт) **побайтно не меняется** — это проверяется assert'ом в
`prepare_source.py` и сверкой в `verify.py`.

Группы изменений (полный список — `patch_scope` в `.local/build/prepare-report.json`):

| Группа | Что сделано |
|---|---|
| **Хост и звук** | `#include "em_web_audio_levels.h"`; масштабирование выхода PSG/DAC по уровню `em_web_audio_level_*`; патч `audio_ymfm.cpp` через `em_web_audio_levels_cpp.h` (`DuneOutputYM2612`, независимые Music/SFX-уровни, read-only копия вклада каналов); `em_web_audio_levels_sync()` при инициализации; выравнивание `audio.sample_index`/`next_sample` к мастер-такту |
| **VDP/растр** | `vdp_render_pixels` → `vdp_render_pixels_reference` (оригинальный попиксельный композитор остаётся oracle/fallback); `#include "em_web_raster.h"`, `em_web_frame.h`; `em_web_frame_capture(c)` сразу после `++v->rendered_frames`; RGBA-композитор развёрнутой карты (`em_web_world_raster.h`, 3→4 байта на пиксель, alpha=255); `em_web_menu_frame()` |
| **Презентация/вид** | общий top-HUD offset для отрисовки и hit-test; портретная раскладка (`em_web_present.h`, `em_web_portrait.h`); drag/pinch-камера вместо edge-hover (прокрутка у края отключена); чистый чёрный clear и удержание мира на переходах; viewport миникарты; видимый фокус нативного меню |
| **Ввод/меню** | `#include` адаптеров `em_web_host.h`, `em_web_camera.h`, `em_web_selection.h`, `em_web_menus.h`, `em_web_menu_select.h`, `em_web_building_ui.h`, `em_web_training.h`, `em_web_campaign.h`; одиночное выделение; preview→confirm для покупок; placement; контекстный B; подмена `em_main_loop_iter` на `em_web_host.h` |
| **Сохранения v2** | `#define DUNE_SAVESTATE_VERSION 2`; строгая проверка при загрузке (`size` в границах буфера, `total_size == size`, `ym_size <= buffer - sizeof(*s)`, `sizeof(*s)+ym_size == size`); после загрузки — сброс `last_frame`/stopped/аудио-очереди/мыши/preview/campaign-состояния и `audio_flush()` |

Ничего из этого не меняет поведение игры: патчи адресуют только хост (SDL-выход,
ввод, презентация) и сериализацию, а не транслированные инструкции и не VDP-тайминг.

## 3. Что даёт преамбула

### C-точки входа (не экспорты)

| Функция | Роль |
|---|---|
| `run_main(argc, argv, rom, size, ea_eeprom)` | инициализация эмуляции и SDL-цикла; вызывается из `main()` сгенерированного ядра (он идёт **после** транслированного кода, не в преамбуле) |
| `sdl_host_service(SDLHost*, CPU*)` | один шаг хоста: событие/тайминг/презентация/аудио |
| `em_main_loop_iter()` | функция кадра для `emscripten_set_main_loop`; в v2 её определяет `em_web_host.h` (через `em_web_main_loop_iter`) |

### `EMSCRIPTEN_KEEPALIVE` в самой преамбуле (5)

- сохранения: `dune_get_save_buffer`, `dune_save_state_to_buffer`,
  `dune_load_state_from_buffer`, `dune_mouse_leave`;
- звук: `dune_web_audio_levels(music, sound)`.

`dune_get_max_save_size` в этом пине **отсутствует** (он появился в более новом
`dune_savestate.h`, которым v2 не пользуется); максимум известен браузерному слою
как константа 262 144 байта (`g_dune_state_buffer[256*1024]`).

## 5. ABI сохранений `DSAV v2`

Сохраняется **ровно структура `DuneSaveState` старой сборки**, иначе импорт старых
сейвов невозможен. Писатель (`dune_save_state_to_buffer`) не менялся; v2 отличается
только номером версии и строгой проверкой загрузки.

Свойства ABI (проверены компиляцией точной структуры из pinned baseline):

- little-endian, **natural alignment, без `#pragma pack`**;
- `sizeof(DuneSaveState) == 140 056`;
- `offsetof(ram) == 94`, `offsetof(sr) == 92`;
- `magic = 0x56415344` (`"DSAV"`), `version = 2`;
- после структуры — дамп YM2612 (`ym_size` байт), `total_size = 140 056 + ym_size`,
  весь поток ≤ `256*1024 = 262 144` байт;
- слова кампании — big-endian u16 внутри RAM: дом по `94 + 0xC274 = 49 874`,
  миссия по `94 + 0xC050 = 49 326` (хранится `mission − 1`).

> ⚠️ В `vendor/rearrakis/genesis_recompiler/dune_savestate.h` сейчас стоит
> `#pragma pack(push, 1)`: если собрать сохранения из этого заголовка, а не из
> pinned runtime, `sizeof` станет **140 027**, `offsetof(ram) == 94` сохранится, но
> PSG/EEPROM/timing поедут, и старые сейвы перестанут читаться. Для `runtime.wasm`
> и любой пересборки использовать только `runtime/dune-runtime-v2.c`
> (или эквивалентный текст), не регенерировать структуру из vendor-заголовка.

| Смещение | Поле | Размер/формат |
|---:|---|---|
| 0 | `magic` | u32 LE = `0x56415344` |
| 4 | `version` | u32 LE = 2 |
| 8 | `ym_size` | u32 LE |
| 12 | `total_size` | u32 LE = длина всего потока |
| 16 / 48 | `d[8]` / `a[8]` | 8×u32 каждый |
| 80 / 84 / 88 | `pc` / `usp` / `ssp` | u32 |
| 92 | `sr` | u16 |
| 94 | `ram[65536]` | 68000 RAM (слова big-endian) |
| 65 630 … 65 646 | `io_data[3]`, `io_control[3]`, `tmss[4]`, `io_tx[3]`, `io_serial_control[3]`, `pad_buttons[3]` | байты |
| 65 649 | `vdp_registers[24]` | байты |
| 65 673 | `vdp_vram[65536]` | байты |
| 131 210 / 131 338 | `vdp_cram[64]` / `vdp_vsram[40]` | u16 |
| 131 418 … 131 424 | адрес/шина/код/флаги VDP | u16/u8 |
| 131 432 … 131 455 | `vdp_data_reads`, `_writes`, `_dma_bytes` | 3×u64 |
| 131 456 … 131 464 | line/clock/hint/irq/vint/pal | u16/u8 |
| 131 472 | `vdp_frames` | u64 |
| 131 480 | `z80_ram[8192]` | байты |
| 139 672 … 139 680 | Z80 bus: requested/reset/bank/ram_writes | u8/u16/u64 |
| 139 688 … 139 720 | регистры Z80 (`r8`, `alternate`, `a/f`, `i/r/iff/im/halted`, `pc/sp/ix/iy/wz`) | u8/u16 |
| 139 728 / 139 736 | `z80_debt` / `z80_steps/cycles/interrupts` | i64 / 3×u64 |
| 139 760 | `psg` | 64 байта |
| 139 824 | `eeprom` | 184 байта |
| 140 008 … 140 048 | `steps`, `cycles`, `master_cycles`, `interrupts`, `instruction_cycles`, `z80_divider`, `halted` | u64/u32/int |
| 140 056 | **конец структуры** | далее `ym_size` байт YM-дампа |

Отличия v2-валидации при загрузке (по сравнению с v1):

```c
// было: только нижняя граница
if (!em_window || size < (int)sizeof(DuneSaveState)) return 0;
if ((int)s->total_size > size) return 0;
// v2: буфер, точное совпадение, границы YM-дампа
if (!em_window || size < (int)sizeof(DuneSaveState) || size > (int)sizeof(g_dune_state_buffer)) return 0;
if (s->magic != DUNE_SAVESTATE_MAGIC || s->version != DUNE_SAVESTATE_VERSION) return 0;
if (s->total_size != (uint32_t)size || s->ym_size > sizeof(g_dune_state_buffer)-sizeof(*s)
    || sizeof(*s)+s->ym_size != (size_t)size) return 0;
```

После успешной загрузки сбрасываются производные состояния: `last_frame=UINT64_MAX`,
`stopped=0`, очищается очередь SDL-аудио, `audio_running=0`, `em_web_audio_flush()`,
сброс мыши/preview/кампании, `camera_valid=0`, `frame=UINT64_MAX`, пересчёт
`audio.sample_index`.

Формат файла-конверта (`dune-sega-web-save` v1) описан в
[SAVES.md](SAVES.md) — рантайм отвечает только за нативный payload.

## 6. Как это будет собираться в `runtime.wasm`

План (в этом репозитории `runtime.wasm` пока **не собран**, emcc не запускался):

- SDK: **Emscripten 3.1.74**, SDL2 (`-sUSE_SDL=2`), C11 для ядра и C++17 для
  YM-драйвера;
- объект ядра: подготовленный `dune-web.c` (игровая часть) или только
  `runtime/dune-runtime-v2.c` + адаптеры для wasm-этапа;
- include-пути: `-Iruntime/adapters` (обязательно: преамбула делает
  `#include "em_web_*.h"`), `-Ivendor/rearrakis/genesis_recompiler` (ymfm/заголовки);
- экспорты — `EMSCRIPTEN_KEEPALIVE` (4 сохранения + `dune_web_audio_levels` +
  70 экспортов адаптеров = 71 `dune_web_*`, см. §3); отдельный
  `EXPORTED_FUNCTIONS` не нужен, что совпадает с проверкой `noGroupExports`;
- `-sEXPORTED_RUNTIME_METHODS='["HEAPU8","UTF8ToString"]'`,
  `-sALLOW_MEMORY_GROWTH=1 -sMAXIMUM_MEMORY=536870912 -sSTACK_SIZE=16777216
  -sINITIAL_MEMORY=67108864 -sASYNCIFY=0`.

Команды (адаптированные из старого `tools/build.sh`; сейчас не запускаются):

```sh
em++ -std=c++17 -O2 -Ivendor/rearrakis/genesis_recompiler -Iruntime/adapters \
     -c .local/build/dune-web-audio.cpp -o .local/objects/audio.o

     -Iruntime/adapters -sUSE_SDL=2 -c .local/build/dune-web.c -o .local/objects/dune.o
em++ -O2 -sUSE_SDL=2 -sASYNCIFY=0 -sALLOW_MEMORY_GROWTH=1 -sMAXIMUM_MEMORY=536870912 \
     -sSTACK_SIZE=16777216 -sINITIAL_MEMORY=67108864 \
     -sEXPORTED_RUNTIME_METHODS='["HEAPU8","UTF8ToString"]' \
     .local/objects/dune.o .local/objects/audio.o -o web/engine/dune_web.js
```

На этапе BYOP-оболочки браузер (Pyodide) только **генерирует C и сверяет SHA** —
компиляция не требуется, поэтому `bundle_web.py` копирует только runtime-файл.
Когда появится `runtime.wasm` (этап 5, см. `docs/WASM-BACKEND.md`), рантайм и
адаптеры компилируются в него заранее, а из ROM генерируется отдельный модуль с
обработчиками; ABI сохранений остаётся тем же, потому что `DuneSaveState` живёт в
рантайме и из ROM не генерируется.

## 7. Воспроизводимость и проверки

```sh
# 1. Проверить MIT-входы и собрать .local (без игровых данных)
python3 tools/bootstrap_core_source.py \
    --baseline "/path/to/Dune Sega Web/vendor/rearrakis/build/dune-base.c"

# 2. Пересобрать подготовленное ядро (0.2 с) и локальные артефакты
python3 tools/prepare_source.py --base "/path/.../dune-base.c"

# 3. Собрать/проверить pinned runtime v2 и манифест (0.3 с)
python3 tools/build_runtime.py --baseline "/path/.../dune-base.c"
python3 tools/build_runtime.py --baseline "/path/.../dune-base.c" --check

# 4. Полная сверка: ROM -> C побайтно == dune-web.c (≈4 с)
python3 tools/verify.py --baseline "/path/.../dune-base.c" \
    --rom "/path/to/Dune - The Battle for Arrakis (USA).gen"

# 5. CI-режим: без ROM/baseline, только статические контракты (0.01 с)
python3 tools/verify.py
```

Результат на текущих пинах: `26 passed, 1 warning, 0 failed in 4.1 s` при
собранном веб-бандле (25 без `web/reference.json`). Единственный warning —
отсутствующий `vendor/rearrakis/LICENSE`; лицензия зафиксирована в
`LICENSE-ReArrakis.md` и `THIRD_PARTY_NOTICES.md`. Без внешних ROM/baseline:
`15–16 passed, 3 warnings, 0 failed in 0.01–0.02 s`. `tools/check_workspace.py`
проходит.

Контракт манифеста (используется `tools/bundle_web.py`, `tools/check_workspace.py`):
обязательные ключи `runtime_file`, `runtime_sha256`, `window_title`,
`shipped_core_sha256`, `shipped_core_bytes`, `recompiler`; плюс описательные
`runtime_bytes`, `baseline_sha256/bytes`, `full_preamble_sha256/bytes`,
`generated_prefix_sha256/bytes`, `savestate`, `adapters`, `exports`,
`vendor_source_manifest_sha256`, `recompiler_overlay`, `prepared_audio_*`.

`.local/` (подготовленное ядро, аудио-драйвер, сгенерированный C, копия
recompiler) — в `.gitignore`, в git не попадает.

## 8. Что пока не сделано / открытые вопросы

1. **`runtime.wasm` не собран.** emcc/emsdk намеренно не запускались; команды в §6 —
   план, а не проверенный билд.
2. **CI не может запустить сверку с ROM/baseline** (игровых данных в репозитории
   нет). `verify.py` деградирует в warnings — это осознанный контракт; полная
   сверка выполняется локально владельцем данных.
3. **`bundle_web.py` не копирует адаптеры**, только runtime-файл. Для Pyodide-этапа
   этого достаточно (C не компилируется), но для будущей компиляции/runtime.wasm
   `runtime/adapters/` должен попасть в include-путь сборки.
4. **`dune_get_max_save_size` отсутствует** в этом пине (есть в более новом
   vendor-заголовке). Если понадобится как часть API — это осознанное расширение
   ABI/экспортов, а не автоматическая регенерация.
5. **Эталонный runtime v1** (спайк, `pinned-runtime.txt`) в git не хранится; в §0
   записаны только его размер/SHA.
6. **Версии WASM/ABI не зафиксированы в браузерном слое** до появления
   `web/reference.json`; `verify.py` проверяет `web/reference.json`, если он есть,
   и предупреждает об устаревании.
7. **`tools/build_runtime.py --check` требует baseline** (он пересобирает преамбулу
   в памяти). Без baseline проверяются только статические контракты через
   `tools/verify.py`.
8. **`tools/check_no_game_data.py` сканирует и gitignored-файлы.** После
   `tools/bundle_web.py` в рабочем дереве появляются `web/py-package.zip` и
   `web/vendor/pyodide/*` (gitignored, в коммит не попадут), на которых проверка
   падает локально; в чистом CI-чек-ауте она проходит. Нужно либо скипать
   gitignored-пути, либо добавить `web/vendor` в `SKIP_DIRS` (зона CI/родителя).
9. **`runtime/reference.json`** — производный файл, его пишет `tools/bundle_web.py`
   (копия `web/reference.json`); в моих артефактах его нет. Если он не нужен в git,
   стоит добавить в `.gitignore` (в нём только SHA/метаданные, игровых данных нет).

## 9. Лицензии и границы данных

- `runtime/dune-runtime-v2.c` — рантайм ReArrakis (MIT, см. `LICENSE-ReArrakis.md`)
  плюс наш MIT-код адаптации; без ROM, без транслированных инструкций, без ассетов.
- `runtime/adapters/*` — наш MIT-код адаптации браузерного хоста/ввода.
- В git/Pages **никогда** не попадают: ROM, `dune-base.c`, подготовленное
  `dune-web.c`, `dune-web-audio.cpp`, сгенерированный C, игровые ассеты, YM-дампы.
  Для них в манифесте хранятся только размер и SHA-256.
- `ymfm` (BSD-3-Clause) и SDL2 (zlib) — внешние зависимости, см.
  `THIRD_PARTY_NOTICES.md`; исходники ymfm лежат в `vendor/rearrakis/`.
- Проверка: `python3 tools/check_no_game_data.py`.
